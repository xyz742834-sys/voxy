# 最適化の方針 — 一般論より実測を優先する

**状態**: 方針の記録。実装は Phase 6 以降。

外部から Apple Silicon 向けの一般論を得たが、**この環境の実測と食い違う点がある**。
どれを採り、どれを採らないかをここに固定しておく。

> **順序**: 最適化は測ってから。Phase 0 から一貫してこの順序でやってきて、
> 実際 MDI の件では<b>一般論のほうが間違っていた</b>。
> いま優先すべきは 5c で実データを動かすこと。
> フレーム時間の内訳が見えてから最適化の議論に入る。

---

## 1. 実測と一致している — 採用済み

### 1.1 UMA によるゼロコピー [確認済 — Phase 0 §4.4]

```
DEVICE_LOCAL | HOST_VISIBLE | HOST_COHERENT | HOST_CACHED が同一メモリタイプ、ヒープは 1 つ
```

**活用済み**:
- `VkBuffer` は全て常時マップ (`addr()` が常に有効)。ステージングバッファを作らない
- `UploadStream` のモード 1 (転送コマンド) を撤去
- 読み戻しも `vkCmdCopyImageToBuffer` → ホスト直読みで済む

### 1.2 descriptor indexing が使える

利用可能だが **現状は未使用**。Voxy 本体が bindless を使っていなかったため。
使う理由がまだ無い。

> 5c 前の調査で **`VK_KHR_push_descriptor` も使える**ことが分かった
> [確認済 — docs/phase5c-mc-vulkan-survey.md §2.4]。
> こちらは descriptor set の更新頻度が問題になったときの選択肢になる。
> **更新頻度を測る前に入れない。**

## 2. ⚠ 実測と食い違う — 採用してはならない

### 2.1 「`vkCmdDrawIndexedIndirect` が Metal の間接描画にダイレクト変換される」は**誤り**

**実測 [確認済 — Phase 0 §2、`docs/phase0-b1-mdi-measurement.md`]**:

| 成分 | 実測値 |
|---|---:|
| 実描画 | **175 ns/draw** |
| degenerate (`indexCount = 0`) | **19 ns/draw** |
| サブミット時処理 (内容非依存) | **30 ns/draw** |

**バッチ効果はゼロ。** 実描画と degenerate が半々の条件が
両者の算術平均に<b>誤差 0.05%</b> で一致した (200,000 件で 19.361 ms vs 19.371 ms)。
これは MoltenVK が 1 コマンドを 1 つの Metal draw に展開していることを意味し、
**Metal の Indirect Command Buffer による GPU 側展開は行われていない**。

**この誤解を採用するとどうなるか**: 「GPU 駆動カリング + 間接描画は高効率」を前提に
セクション単位 88,000 draws を維持すると **18.0 ms = 予算の 12 倍**。
だから 88,000 → 7 draws の統合 (二分探索による逆引き) が必要だった。

> **統合の目標は「1 draw」ではなく「1,000 draws 以下」で十分**という点も実測由来である
> (1 draw と 1,000 draws の差は 0.5%)。ここも一般論からは出てこない。

### 2.2 Mesh Shader のフォールバック維持 — **該当しない**

Voxy には `ShaderType.MESH` / `TASK` の enum があるだけで<b>使用箇所がゼロ</b>。
維持すべきフォールバックが存在しない。

## 3. 未着手だが Phase 6 で検討する価値がある

### 3.1 TBDR 特性 — `LAZILY_ALLOCATED` メモリ

Phase 0 で `memType[2]` に `LAZILY_ALLOCATED` を確認したが未使用。
「タイル内で完結して実メモリに書き戻さない」中間バッファに使える可能性がある。

**⚠ ただし制約が 2 つある**:

1. **subpass + input attachment は現設計と噛み合わない。**
   `dynamic_rendering` を採用済みで、これは<b>subpass を使わない</b>方向の機能である
   (Vulkan 1.4 に上げた目的の 1 つ)。
   タイルメモリの利得を最大化するには subpass 構成に戻す必要があり、
   `VkRenderTarget` / `VkGraphicsPipeline` の設計を巻き戻すことになる

2. **interop の制約。** 描画結果を IOSurface 経由で GL に渡す以上、
   **実メモリへの書き戻しは必須**である。
   `LAZILY_ALLOCATED` が使えるのは<b>中間バッファだけ</b>で、
   最終的な色・深度には使えない

→ 効く余地は「Vulkan の中で閉じた中間結果」に限られる。
測ってから判断する。

---

## 4. 記録の理由

Phase 0 の B-1 では、一般論 (「Metal の ICB に落ちるから MDI は速い」) を信じていたら
**設計ごと間違えていた**。実測が設計分岐を決めた。

同じ型の間違いを繰り返さないため、
<b>「一般論として正しいこと」と「この環境で測れたこと」を分けて記録する</b>。
食い違ったときは実測を採る。
